# 基本介绍

Umo Editor Next 的文档表单能力，不是传统的“纯页面表单组件”，而是把变量能力直接嵌入文档正文中，让业务系统围绕“模板设计 -> 程序填充或人工填写 -> 数据收集 -> 结果导出 / 展示 / 存档”构建完整链路。

它也非常适合批量生成文档：业务系统可以基于同一份模板批量传入不同变量值，快速生成多份内容不同但版式一致的正式文档，并进一步结合 Umo Editor Next 的导出能力，批量产出 Word、PDF、图片等交付文件。

## 适用读者

- 想先快速理解“文档表单”到底是什么
- 正在判断它是否适合自己的业务
- 想知道它和模板、导出、评论、修订这些能力怎么配合

## 你可以先记住三件事

- 它不是孤立的表单组件，而是一套“文档模板 + 变量 + 数据回收 + 出文”的完整链路
- 它既支持人工填写，也支持程序批量生成
- 它特别适合标准化文档、批量出文、结果归档和结构化数据回收

## 能力地图

| 能力 | 面向谁 | 解决什么问题 |
| --- | --- | --- |
| 模板设计 | 模板制定人 | 把标准文档做成可复用模板 |
| 人工填写 | 业务填写人 | 收集字段值并做校验、提交 |
| 程序填充 | 业务系统 / 后端 | 按变量自动生成不同结果文档 |
| 结果展示 / 导出 | 审批人 / 查看人 / 对外交付 | 查看最终结果、归档、导出正式文件 |

它特别适合这类企业文档：

- 合同、协议、承诺书、授权书、告知函、申请单、审批单、确认单、回执单
- 报告、通知、函件、公告、通报、证明、说明书、登记表、信息采集表、问卷与表单
- 招聘录用、入职办理、采购审批、项目交付、财务报销、行政流转、人事异动等标准化业务文档
- 医疗健康场景中的电子病历、入院记录、出院小结、检查申请单、知情同意书、随访记录
- 教育培训场景中的报名表、学籍登记表、成绩说明、培训签到单、实习鉴定表
- 政务与公共服务场景中的申报材料、备案表、审批表、回执单、证明材料
- 个人或小团队高频使用的简历、报价单、合作确认单、活动报名表、服务记录单

## 解决了什么问题

很多企业的“文档填写”场景，本质上都同时存在这几个问题：

- 模板骨架经常被误改，导致格式和条款不一致
- 同一类文档需要反复替换人员、日期、金额、项目名等字段
- 前端手工拼 HTML 或后端字符串替换，难以保证复杂排版稳定
- 填写结果不受校验约束，容易漏填、错填、格式不合法
- 填写后的字段值难以结构化回收，无法直接用于保存、审批、统计和后续业务流转
- 生成结果和审批、评论、导出、存档等环节脱节
- 系统已有部分字段时，缺少“先预填、再补录、再提交”的自然链路

文档表单能力的目标，就是把这些问题收口到一条统一链路里：

1. 由模板制定人预先设计文档模板与变量位
2. 由业务人员填写，或由后端程序批量传值生成文档
3. 在填写和生成过程中同步完成结构化数据收集，便于业务系统保存变量值、发起流程、做统计分析
4. 在生成前后继续复用导出、评论、修订、锁定、协作等能力
5. 生成后的文档既可以继续编辑，也可以作为只读结果展示，也可导出为正式文件
6. 支持把历史结果或系统已有数据回填为 `form.values`，承接草稿恢复、驳回补填、系统预填后人工补录

## 功能清单

- 在正文中插入文本、数字、日期、单选、多选、下拉、富文本等变量
- 文本类变量支持直接沿用正文行内格式，生成结果会保留加粗、颜色、高亮等样式
- 支持图片、签名、印章、二维码、条形码等图片类变量
- 图片类变量支持尺寸与展示属性设置，如宽高、自适应高度、等比缩放、浮动拖拽；印章变量还支持预设尺寸
- 支持模板设计、表单填写、结果预览、程序填充四类工作方式
- 支持必填、格式校验、自定义类型规则、提交回调
- 支持把填写结果作为结构化变量数据回收，用于保存、审批、统计和归档
- 支持通过实例方法或初始化配置传入变量值，批量生成不同文档
- 支持生成后作为只读结果展示，也支持退出表单链路后继续按普通文档编辑
- 支持与 Umo Editor Next 导出链路衔接，批量输出 Word、PDF、图片等正式文件
- 支持输出最终内容的 `html / json / text`

## 与其他功能协同使用

文档表单不是孤立功能，它通常与其他能力组合落地：

- 与[模板管理](./template)配合：管理模板来源、分类、上下架
- 与[内容锁定](./locked)配合：保护模板骨架，只开放变量区
- 与[文档导出](./export)配合：输出 Word / PDF / 图片等最终稿，也适合在业务侧循环调用形成批量 PDF / Word 出文链路
- 与[文档批注](./comments)配合：对填写说明、异常项、审批意见进行讨论
- 与[文档修订](./revision)配合：模板维护阶段记录条款修改痕迹
- 与[历史版本](./versions)配合：保留模板发布节点和生成结果快照
- 与[多人协作](./collaboration)配合：多人共编模板或共同补充填写内容
